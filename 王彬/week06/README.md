## 4. 分诊口径（labels.py 的业务设计）

```
15 科室 ──GROUP_MAP──▶ 4 组去向 ──RELEVANT──▶ 队列路由（queue_name）

慢病随访（呼吸/消化/神经/内分泌/肝病）          → consult   标准在线问诊，医生按序接
女性健康（妇科/产科）                            → consult   同上（妇产科专线）
手术转诊（普外/神外/泌尿/肛肠）                  → priority  高置信→线下绿色通道；低置信→triage
重点专科（儿科/男科/肿瘤/心血管）                → priority  同上（高风险/私密专线，优先调度专科医生）
```

> 口径依据是**资源调度方式**，不是医学分类——心血管内科按医学是内科，但按分诊是高危优先，
> 这是产品定义。和老师版「金融+产业=投研相关」是同一种设计思想：相关性由业务派生，零标注。

评测口径：同一批「去重后的干净验证样本」500 条（seed=42），三者完全可比。

| 方法 | 医疗（我的实测） | TNEWS（老师 README） | 变化 |
|---|---|---|---|
| 规则/关键词 | 0.588 / 0.574 | 0.126 / 0.072 | **+46.2 点**：症状词直接指向科室（TNEWS 只有 6% 的标题含类别名） |
| TF-IDF+SVM | **0.838 / 0.786** | 0.512 / 0.472 | **+32.6 点**：症状/器官词的词面信号极强 |
| BERT 微调 | 0.814 / **0.790** | 0.556 / 0.544 | +25.8 点，但**准确率反而低于 TF-IDF 2.4 点** |

### 训练前的预判，被验证了吗

> 原预判：医疗短文本词面信号强，TF-IDF 已到 0.84，BERT 还能领先多少？

**验证结果：BERT 没有领先，准确率反而输了 2.4 点；只有 Macro-F1 赢了 0.4 点。**

推论：科室分诊是**词面信号主导**的任务——"咳嗽"就是呼吸内科、"月经"就是妇科，
词的组合与上下文几乎不贡献额外信息，所以 BERT 的语义建模能力在这里无处发力。
这与老师版「封闭标签 + 短文本 → BERT 最划算」形成互补：
**封闭标签 + 短文本 + 强词面信号 → 判别式浅层模型反而更划算**。

而 Macro-F1 上 BERT 反超，说明它在**长尾科室**（泌尿外科 1,358 条、肝病科 1,540 条）
上比 TF-IDF 更稳——类别不均衡时准确率和 Macro-F1 会给出相反结论，这是必须同时报两个指标的理由。

### 消融实验：类别加权与 FGM（回应「罕见病误判」）

老师的关切：医疗分诊里罕见病误判代价高，应该用**类别加权（尤其长尾）+ FGM 对抗训练**降低误判。
本项目在**全量干净验证集 9,926 条**上做了三组对照（同一训练集、同一 seed=42、3 epoch、其余配置不变）：

| 实验 | 配置 | 准确率 | Macro-F1 | ECE | 训练耗时 |
|---|---|---|---|---|---|
| E0 | 加权 on / FGM off（默认基线） | 0.8120 | 0.7817 | 0.0675 | 264 秒 |
| E1 | **加权 off** / FGM off | **0.8365** | **0.7975** | **0.0443** | 264 秒 |
| E2 | 加权 on / **FGM on**（ε=1.0） | 0.8124 | 0.7840 | 0.0563 | 440 秒 |

**① 本数据上关掉类别加权反而全面更好**（准确率 +2.45、Macro-F1 +1.58、ECE −0.023）。

原因是不均衡度只有 **8.7×**，没到课件 P24 说的 **100× 阈值**。加权把妇科（22.2%）的权重从 22% 压到 1/15，
四个尾部类被放大 3~8 倍后在小样本上过拟合——头部受损、尾部没赚回来。

**这不是推翻课件，而是验证了它的阈值判据**：
> 「什么时候这些旋钮才值钱：类别更多更不均衡（>100×）、或数据量小到明显过拟合」

**② FGM 在加权基础上是微小正收益，但 ECE 改善明显**（0.0675 → 0.0563，−17%）。
Macro-F1 只涨 0.23 点，和课件在 TNEWS 上的 +0.02 同量级；但校准变好意味着
「置信度 0.8」时实际命中率更接近 80%，低置信转人工的闸门才敢用。
代价是训练时间 ×1.67（264 → 440 秒）。

**③ 长尾类没有被「吃掉」，recall 与训练量基本无关。**

加权基线的 per-class recall（500 条干净集）：

| 科室 | 训练量 | recall |
|---|---|---|
| 泌尿外科 | 1,358（最少） | 0.846 |
| 肝病科 | 1,540 | **1.000** |
| 内分泌科 | 1,602 | 0.867 |
| 心血管内科 | 1,682 | 0.800 |
| 产科 | 1,704 | 0.722 |
| 妇科 | 11,848（最多） | 0.769 |

样本最少的肝病科召回 100%，样本最多的妇科只有 76.9%。
说明这份医疗数据的难点在**类间语义边界模糊**（产科 ↔ 男科 ↔ 儿科、心血管内科 ↔ 神经内科），
而不是「样本少」——所以加权的靶心没打中真正的痛点。

> **诚实说明**：8.7× 的不均衡度不足以触发加权的收益区间，本实验**无法直接证明**「加权能降低罕见病误判」。
> 要验证这一点需构造 >100× 的长尾子集（把尾部类降采样到 120 条左右），
> 但那样得到的是人为造的数据分布，且不影响本报告「词面信号主导」的主结论，故列为后续可选实验。

### 7.1 没有 GPU 的影响与最终处置（已解决）

本机诊断：`torch.cuda.is_available() == False`（装的是 CPU 版 torch），
`nvidia-smi` 不存在，`Win32_VideoController` 只报告 **Intel Iris Xe 集显（共享显存）**——
**确认这台机器没有独立 NVIDIA 显卡**，不是 torch 装错版本。

**最终选择：借云 GPU，且不降级——全量数据、全量 epoch 跑完。**

| 方法 | 老师给出的 GPU 耗时 | 我的实测（A10 24G） | 是否降级 |
|---|---|---|---|
| 规则 / TF-IDF | 20 秒 | 4 秒（本机 CPU） | 无 |
| BERT 微调 | ~14 分钟 | **264 秒** | 无（53,360 条 × 3 epoch 全量） |
| Qwen 零样本 500 条 | ~5 分钟 | **30 秒** | 无 |
| Qwen + LoRA | 44 分钟 | **337 秒** | 无（5,000 条 × 2 epoch） |

实测比老师给出的估算快很多，说明那组耗时数字偏保守（也可能是更老的卡）。
未采纳「纯 CPU 降级跑」，因为降级后绝对数字不可与老师版直接对比，违背 week5 的「保口径」原则。

> 已排除「重装 GPU 版 torch」这条路径：物理上没有 NVIDIA 显卡，装了也用不上。

| Qwen+LoRA SFT | 0.806 | 0.7585 | 15/15 | 337 秒训练（A10） | 6 亿参数小模型追平 BERT |
| Qwen 全量微调（选做） | — | — | — | — | 本轮未做，资源允许可补 |

> 全量 val（10,000 条，含 74 条重复）上 BERT 3 个 epoch 的准确率为 0.7948 → 0.8069 → 0.8125，

## 11. 复盘：三个可复用的结论

**① 「该不该上大模型」取决于任务的信息分布，不取决于模型新旧。**

医疗分诊的答案几乎完全由关键词决定（"咳嗽"→呼吸内科），所以 TF-IDF 用 4 秒达到 0.838，
比训练 264 秒的 BERT 还高 2.4 个点。反过来，如果任务依赖上下文推理
（如新闻标题里的"暴跌"要结合领域判断是证券还是财经），BERT 的优势才会显现。

**② 零样本在封闭标签体系上不可用，微调是必需的。**

同一个 0.6B 模型，零样本 0.194（只覆盖 9/15 类），LoRA 微调后 0.806（覆盖 15/15）。
提升 4.2 倍，而只训练了 0.38% 的参数、花了 337 秒。这说明：
**有标注数据时，微调小模型的性价比远高于用提示词榨大模型。**

**③ 准确率和 Macro-F1 会给出相反的结论，必须同时报。**

| 方法 | 准确率 | Macro-F1 | 谁更好 |
|---|---|---|---|
| TF-IDF | **0.838** | 0.7863 | 准确率赢 |
| BERT | 0.814 | **0.7902** | Macro-F1 赢 |

8.7 倍的类别不均衡（妇科 11,848 vs 泌尿外科 1,358）下，TF-IDF 靠多数类拉高准确率，
而 BERT 在长尾科室上更稳。产品落地时如果长尾科室漏诊代价高（如肿瘤科），
应该优先看 Macro-F1 而不是准确率。

## 12. 踩过的坑（留给下一个复现的人）

| 坑 | 现象 | 原因 | 解法 |
|---|---|---|---|
| `dtype=` 参数不被识别 | `Qwen3ForCausalLM.__init__() got an unexpected keyword argument 'dtype'` | `dtype=` 是 transformers 4.56+ 的新参数名，4.55 只认 `torch_dtype=` | 把 `from_pretrained(...)` 里的 `dtype=` 改成 `torch_dtype=` |
| 全局替换误伤 | `torch.full(..., torch_dtype=torch.long)` 报 `full() received an invalid combination of arguments` | 用正则批量替换时把 `torch.full` / `torch.autocast` 的正常 `dtype=` 也改了 | 只能逐处精确替换，或只对 `from_pretrained(` 内部做替换 |
| zip 用反斜杠 | `warning: appears to use backslashes as path separator` | Windows 的 `Compress-Archive` 打包时用 `\` 作分隔符 | 用 Python `zipfile` 写入，路径用 `as_posix()` |
| 工作目录猜错 | `unzip: cannot find or open cloud_upload.zip` | 以为在 `/mnt/workspace`，实际终端在别的目录 | 先 `pwd` 确认，再 `find /mnt -name "*.zip"` 定位 |
| 大文件打包 | `week6_results.tar.gz` 有 371 MB | 把 `bert_ckpt.pt`（约 400 MB）一起打进去了 | 只打包 `*.json *.md *.txt` 和 `lora_adapter`，几 MB 即可 |

### 13.6 对老师问题的直接回答

**问：加权和 FGM 能不能降低罕见病误判？**

**答：在「罕见病 = 样本少的科室」这个前提下，本数据不支持这个假设，原因是前提不成立。**

三点说明：

1. **本数据的「少样本类」并不难分。** 肝病科只有 1,540 条，recall 100%；泌尿外科 1,358 条，recall 84.6%。
   它们靠「转氨酶」「前列腺」这类强特征词就能区分，不依赖样本量。
2. **真正的误判发生在语义相近的类之间，而不是大类吃掉小类。** 产科被误判到男科、儿科，
   心血管内科被误判到神经内科——这些需要的是**更好的标签口径或上下文信息**，不是加权。
3. **加权和 FGM 要发挥作用，需要 >100× 的极端长尾。** 若要复现课件场景，需把尾部类降采样到 120 条左右
   （不均衡度 8.7× → 约 99×），但那是人为数据分布，与本报告主结论无关，列为可选后续实验。

# week5 作业：用一套指令数据，给语言模型做 SFT

> 承接第 4 周：上次你训的是一个**只会续写的字符级语言模型**（「接龙器」）。
> 这次不动模型结构，只换**数据和 loss**，用一份「问题 → 回答」的数据做一遍标准的 SFT。
>
> 就是课上说的那句：**SFT 改的是数据，不是结构**。

---

## 一、目录里有什么

| 文件 | 作用 |
|---|---|
| `corpus_pretrain.txt` | 75 万字预训练语料（基座用） |
| `sft_train.jsonl` | 3000 条训练用「问题 → 回答」 |
| `sft_val.jsonl` | 200 条验证用（**训练时绝对没见过**，评测只能用它） |
| `transformer_lm.py` | 训**基座**（第 4 周那份代码 + 特殊标记 / padding mask / 联合字表） |
| `sft.py` | 做 **SFT**：拼模板 + loss mask + 训练 + 评测（**本次作业的主体**） |
| `demo_sft.py` | 同一道题，看「SFT 前 / SFT 后」 |
| `fit_check.py` | 检查模型在训练集/验证集上的拟合程度（第五节用） |
| `base_lm.pt` | 已经训好的基座（不想等训练可以直接用） |
| `sft_mask.pt` | 已经训好的 SFT 模型（参考结果，`demo_sft.py` 默认加载它） |
| `sft_fit.pt` | 12M 的「背下来」版本，训练集 exact match 83%（第五节） |

数据来自公开指令集 **BelleGroup/train_0.5M_CN**（GPL-3.0），按「问句 4~48 字、回答 2~64 字」筛过，
再从 25,914 条候选里用固定 seed 抽了 3000 + 200（已打包在这，**不需要联网**）。

为什么非要筛短：咱们是**字级**模型、上下文只有 128 个字。主流指令集的回答中位数 60~280 字，
不筛的话一条样本光回答就超长，模型根本学不动。

## 三、参考结果（本机 RTX 4060，固定 seed=42）

**规模**：2.60M 参数（d=192 / 4 层 / 4 头 / 窗口 128），字表 4136 个字符（含 3 个特殊标记）

| 模型 | 训练方式 | 验证集「回答段」PPL |
|---|---|---|
| SFT 前（基座） | `corpus_pretrain.txt`，16 epoch | **391.89** |
| SFT 后 | 从基座接着训 3000 条，10 epoch | **17.50** |

基座自己的预训练 PPL（按字算）是 **46.22** —— 它「续写」得还行，但换成答题就露馅了。

问答环节长这样（`demo_sft.py` 的输出，验证集里的题）：

```
问      ：将以下句子转换为被动语态。 句子： Tom 发现了一份工作。
参考答案：一份工作被Tom发现了。
SFT 前  ： 请问您是输入一下您的手机号码的，辛苦您了。 谁知道这是什么   ← 又在「接着问」
SFT 后  ：" " " " "，这句子1：时间"时间 "，"现在开始为 的时间数。        ← 学会作答了，但答得不对
```

两点要说清楚：

- **格式对了**：SFT 后模型会在 `<|assistant|>` 后面开始作答、说完自己停（输出 `<|end|>`），
  PPL 从 391 掉到 17.5，说明它确实学到了「在这个位置该写答案」；
- **答不对是正常的**：2.6M 的字符级模型学不会真知识。这次作业考的是**机制** ——
  模板怎么拼、loss 怎么 mask、评测口径怎么统一，不是回答质量。

## 五、进阶：让它「把训练集背下来」（可选）

默认那套跑完，训练集里的题它也答不利索。想看到「集内拟合」的效果，要同时改两件事：

### 1）先避开一个坑：`--save-best`

`sft.py` 默认 `--save-best val`（只存验证集最好的那轮）—— 这是**正经训练**该有的行为。
但你一旦开始过拟合，验证集从第 2 轮起就一路变差，于是**存下来的是最早那轮的模型**。
现象就是「日志里训练 loss 都 0.004 了，加载回来还是不会答」。

想看「背下来」的效果，必须加 `--save-best last`。

### 2）换大点的模型 + 多训几轮

```bash
# ① 12M 基座
python transformer_lm.py --d_model 384 --heads 8 --layers 6 --epochs 16 --save base_lm_12m.pt

# ② SFT：60 轮，存最后一轮
python sft.py --base base_lm_12m.pt --epochs 60 --lr 1e-3 --save-best last --save sft_fit.pt

# ③ 看结果
python fit_check.py --ckpt sft_fit.pt          # 训练集
python fit_check.py --ckpt sft_fit.pt --val    # 验证集（对照）
```

仓库里已经放了一份训好的 **`sft_fit.pt`**（12M），不想等 20 分钟可以直接：

```bash
python fit_check.py --ckpt sft_fit.pt --n 200
```

### 3）结果（本机实测）

| 配置 | 训练集 teacher-forcing | 训练集 exact match | 训练集字符 F1 | 验证集 exact match |
|---|---|---|---|---|
| 2.6M / 10 轮 / 默认 save | 61.1% | 0% | 0.422 | — |
| **12M / 60 轮 / `--save-best last`** | **99.3%** | **83.0%** | **0.958** | **0%** |

```
Q   : 计算一组数字的平均值和标准差。 数字：23, 45, 67, 89, 12
gold: 这组数字的平均值为47.2，标准差为33.41。
pred: 这组数字的平均值是32.2，标准差为33.43。     ← 格式全对、数字差一点
```

### 4）这说明什么（推荐写进作业结论）

- **能背**：3000 条 × 60 轮之后，训练集上 83% 的答案能一字不差复现；
- **没学会**：同一个模型在验证集上 exact match 是 **0%**，字符 F1 只有 0.41；
- 这就是**过拟合**最直白的样子 —— 记忆 ≠ 泛化。真实 SFT 要几十万条数据、要留验证集做早停，原因就在这里。

## 八、常见坑（踩过就省半小时）

1. **字表不一致**：`sft.py` 的 `char2idx` 必须从 ckpt 里读，不能自己再建一个 ——
   否则同一个字在两边 id 不同，模型看起来「训了但没效果」。
2. **标签整体错一位**：忘了 `y[t] = S[t+1]`，模型输出的第一个字会是模板而不是答案。
3. **padding 只 mask 了 loss，没 mask 注意力**：`-100` 只让 loss 跳过，
   注意力还是会看到填充字符，得再把 `key_padding_mask` 传进去。
4. **忘了 `model.eval()`**：dropout 没关，同一个问题每次生成都不一样，PPL 也偏高。
5. **拿基座的 46 去比 SFT 的 17**：这两个数不是同一口径（一个是按字算的预训练 PPL，
   一个是只算回答段的）。要横向比就看 `demo_sft.py` 最后那两行。
6. **超长样本直接扔**：本仓库的做法是「砍回答尾巴、保住模板和问题」，
   因为模板和问题是「答在哪个位置开始」的锚点，砍掉它就学废了。
7. **以为答案是错的就说明代码错了**：2.6M 字符级模型答错是**正常**的，
   `sft_val.jsonl` 的参考答案只用来算 PPL，不用来判对错。
8. **训练 loss 都 0.004 了，加载回来还是不会答**：八成是 `--save-best val` ——
   过拟合后验证集一路变差，存下来的是最早那轮的模型。想看「背下来」加 `--save-best last`。

## 九、和课件怎么对应

| 课件 | 这里 |
|---|---|
| SFT = 把「续写器」变「问答助手」 | 基座（只会接龙）→ SFT 后的模型 |
| chat template | `<|user|>问题<|assistant|>回答<|end|>` |
| Loss Mask（×不计算 / √计算） | `SFTDataset` 里 `y[t] = -100` 那几行 |
| ignore_index=-100 是 PyTorch 约定 | 训练里那行 `F.cross_entropy(..., ignore_index=-100)` |
| SFT 数据量「几万条」 | 这里只用了 3000 条：小模型 + 小数据，够把机制跑通 |

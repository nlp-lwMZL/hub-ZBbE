## 1、从二分类到多分类

二分类：模型输出一个数，大于 0.5 算一类，小于 0.5 算另一类。

多分类：一个样本可能属于好几类中的某一类。模型的输出不再是 1 个数，而是**每类一个分数**，最后挑分数最高的那类。

- 二分类：输出 1 个数（概率）
- 多分类：输出 N 个数（N 个类别的分数），取最大值下标就是预测类别

这次的作业题目就是：**给一个任意 5 维向量，它最大的数字出现在第几维，就属于第几类**。比如 `[0.1, 0.6, 0.3, 0.2, 0.5]`，第 1 维（下标 1）最大，所以它属于第 1 类。

## 2、logits 和 softmax

模型最后一层线性层输出的原始分数叫 **logits**，它可以是任意实数，可正可负，加起来也不等于 1，不能直接当概率看。

要让它们变成概率，就过一遍 **softmax**：

```
softmax(zi) = e^zi / Σ(e^zj)
```

- 每个数先取指数，保证都是正数
- 再除以所有指数之和，保证加起来等于 1
- 指数放大了差距：分数高的类概率会被拉得更大

所以 logits 只是“相对大小有意义”，softmax 之后才变成“各类别概率”。

## 3、交叉熵损失（cross entropy）

多分类用的损失函数是交叉熵，衡量“模型给出的概率分布”和“真实答案”差多远。

真实答案一般是**类别下标**（0~4），可以想成 one-hot 向量：属于第 2 类就是 `[0,0,1,0,0]`。

```
loss = -Σ yi * log(pi)
```

带入 one-hot 之后，只有正确那一项留下：

```
loss = -log(正确类别的概率)
```

含义很直白：

- 模型给正确答案的概率越接近 1，`-log()` 越接近 0，loss 越小
- 模型给正确答案的概率越接近 0，loss 越大，惩罚越狠

这就是为什么交叉熵配 softmax 是分类任务的标配：**它只关心正确那类的概率有多高**。

## 4、PyTorch 里的实现
输出层从 1 个神经元换成了 5 个：

```python
self.linear = nn.Linear(input_size, class_num)   # 5 输入 -> 5 输出
self.loss = nn.functional.cross_entropy           # logits + 标签，直接算 loss
```

几个关键点：

- `nn.Linear(5, 5)`：输入 5 维，输出 5 个 logits
- `nn.functional.cross_entropy(logits, y)` 内部已经做了 softmax，**不要再手动 softmax 一次**，否则相当于做两遍
- `y` 必须传**类别下标**（long / int64），不需要手动转 one-hot
- 预测时先 `torch.argmax(logits, dim=1)` 拿类别，需要看概率再 `torch.softmax`

生成数据的逻辑：随机生成 5 个数，`np.argmax` 拿最大值的下标当标签。

## 5、训练流程

和回归任务完全一样的四步，没有变：

1. 前向传播：`logits = model(x)`，再算 `loss = cross_entropy(logits, y)`
2. 反向传播：`loss.backward()` 求梯度
3. 更新参数：`optimizer.step()`
4. 清空梯度：`optimizer.zero_grad()`

细节：

- **按 batch 训练**：1000 条样本分成 50 个 batch，每个 batch 20 条，一个 epoch 更新 50 次参数
- **优化器**：这次用的 Adam，学习率 0.1。Adam 会自己调整每个参数的学习率，比纯 SGD 收敛快
- **随机种子**：训练前固定 `np.random.seed()` 和 `torch.manual_seed()`，保证每次跑出来结果一样，方便对比
- 每轮训练完在 200 条新样本上评估一次，记录 loss 和准确率，最后画曲线观察

## 6、评估和预测

评估就是拿一批**没参与训练**的数据，看模型猜对多少：

```python
pred = torch.argmax(logits, dim=1)
correct = torch.sum(pred == y).item()
acc = correct / total
```

预测分两步：

1. 训练完 `torch.save(model.state_dict(), "multi_class_model.bin")` 保存权重
2. 用的时候重新建一个同结构的模型，`load_state_dict` 把权重装回去，再 `eval()` + `no_grad()` 推理

`load_state_dict` 要求结构和保存时**完全一致**（输入 5 维、输出 5 类），否则会报 key 不匹配。

本次实测 20 轮后准确率稳定在 **92%~96%**，预测演示里有一个边界样本（0.8873 vs 0.8778 很接近）也判断正确，说明线性层确实学到了“比较大小”这个规律。

## 7、踩过的坑

1. **标签类型必须是 long**
   一开始图省事用 `torch.FloatTensor(Y)` 装标签，训练直接崩：
   `RuntimeError: expected scalar type Long but found Float`
   交叉熵要的是整数类别下标，必须 `torch.LongTensor` / `dtype=np.int64`。

2. **不要把 numpy 数组列表直接塞给 tensor 构造函数**
   `torch.FloatTensor([ndarray, ndarray, ...])` 能跑，但会报性能警告。正确做法是先 `np.array(...)` 变成整体数组，再 `torch.from_numpy()`。

3. **`cross_entropy` 自带 softmax**
   如果先 `softmax` 再传给 `cross_entropy`，等于做了两次，loss 会不对，梯度也变差。

4. **预测和训练的开关要记得切**
   `model.train()` / `model.eval()` 影响 Dropout、BatchNorm 等层的行为，这次虽然没用这些层，但养成习惯。

## 总结

多分类的核心就三句话：

- 输出层给每类一个 logits，取最大值下标当预测结果
- softmax 把 logits 变概率，交叉熵衡量预测概率和真实类别的差距
- 训练流程和回归一模一样，变的只是输出维度、损失函数和评估方式（比准确率而不是比误差）

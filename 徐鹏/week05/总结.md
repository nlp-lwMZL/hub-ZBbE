《从 BERT 到大模型》精简总结
1. 文本生成原理
语言模型给前文，预测下一个 token 的概率分布。
生成是外部循环：每步选一个词拼回输入，再算一次，直到 EOS 或达到长度上限。
选词策略：
确定性：贪心（Greedy）、Beam，适合代码 / 数学 / 翻译等有标准答案的任务。
随机采样：温度 T、Top-K、Top-P；T↓ 更尖锐，T↑ 更发散。
2. BERT 为什么不能生成（三宗罪）
目标不匹配：MLM 是完形填空，生成是续写。
注意力双向：每个位置能看到后面的词，等于提前看答案。
输出长度由输入决定：无法自己决定写多长、何时停下。
改造只需三处，结构参数不变：
换目标：MLM → next-token 预测；
换 mask：全可见 → 下三角因果掩码；
换用法：一次前向出结果 → 生成循环，拼回输入再前向。
配套概念：三种 mask 模式、自回归训练（teacher forcing）、KV Cache。

4. 大模型的规模与效果
ChatGPT 时刻：质变而非量变 —— 一模型多任务、自然语言即接口、零样本泛化。
Scaling Law：参数、数据、算力呈幂律，规模上涨 loss 按幂律稳定下降，可按预算预测效果。
涌现能力：部分能力到规模阈值后台阶式出现（ICL、CoT、多步推理、指令遵循）。
ICL：不改权重，用 prompt 里的示例换任务，新任务零数据成本。
CoT：让模型把推理过程写出来，分解问题、可自我纠错；规模依赖，小模型用 CoT 反而更差。
5. SFT：让续写器变成问答助手
仅预训练的 Base Model 只是 "概率续写器"，会接着列问题，而不是回答。
SFT 做什么：用几万～几十万条指令对话数据 + chat 模板；只改数据、loss 和模板，不加新层，目标仍是 next-token。
Loss Mask：prompt 段标 -100 不参与 loss，只对回答段计算，只学 "怎么答"，不背 "问什么"。
没变的：架构、因果 mask、训练目标、推理方式；变了的：输出分布、对话协议、停止行为、表达风格。
三阶段全景：
预训练：万亿 token 无标注语料，给语言能力与世界知识；
SFT：指令数据 + Label Mask，教会被问就答、答完就停；
对齐：人类偏好反馈（RLHF / DPO / GRPO），让回答更符合偏好、更安全。
知识来自预训练，形式来自 SFT，偏好来自对齐，三者不能互相替代。
6. LLM API 调用落地
三条路径：闭源 API（最快、按 token 付费）、开源权重自部署（最可控）、自微调（最贴业务）。
OpenAI 兼容三件套：base_url、api_key、model；换平台只改两行。
messages：模型本身无记忆，多轮历史需逐条回传；system 定身份规则，user 是本轮输入，assistant 是历史回答。
非流式：全部生成完才返回，适合批处理；流式（SSE）：边生成边推送，首字延迟决定体验。
计费：输入、输出分别计价，输出通常贵 2~4 倍；max_tokens 与历史长度直接等于成本。
生产防护：重试 + 指数退避 → 断路器 → 多 Provider 主备切换与主动探活。
总结：一张图串起全课
BERT（双向理解）
  → 换 mask → Causal LM（会接龙）
  → 预训练 next-token（有知识）
  → SFT 指令数据（会回答）
  → 采样 + API（落地上线）

贯穿全课的一句话：结构几乎不变，变的是 mask、数据、loss 落在哪、参数怎么采样。同一个 Transformer，从 "理解" 走到 "能上线"，只换了这四样东西。
八条要点
BERT 不能生成：目标、mask、长度三处都不匹配。
一个矩阵定任务：全可见 = 理解，下三角 = 生成。
训练并行、推理串行：teacher forcing 与 KV Cache。
生成 = 受约束抽样：T /top-k/top-p 三件套。
三范式各有主场：通用助手赛道 decoder-only 赢。
规模可预测、能力有阈值：Scaling Law + 涌现。
知识 vs 形式：预训练给知识，SFT 给形式。
API 三件套：base_url /key/model + 重试与故障转移。

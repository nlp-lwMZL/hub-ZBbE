# service/ —— L5 系统组合（可演示的服务层）

**一句话**：把「检测器 → 事件抽取模型 → 规则兜底 → 校验 → 篇章合并 → needs_review」串成一条可调用的服务。
它回答的问题是：**模型指标不错了，为什么还不能直接上线？**

```bash
python service/demo_extract.py --n 3                      # 现场演示：打印 3 篇公告的事件流
python service/demo_extract.py --doc_id <公告id>          # 指定公告（逗号分隔可多篇）
python service/demo_extract.py --n 1 --no_fallback        # 关掉正则兜底，看模型原始能力
```

| 文件 | 作用 |
|---|---|
| `extract_service.py` | `ExtractService`：加载模型 + 逐句抽 + 校验/兜底 + 篇章合并 + 置信度/needs_review |
| `demo_extract.py` | 命令行演示（切句数、逐句过程、最终事件流 JSON、与金标对照） |

**四个工程点（课堂上逐个讲）**
1. **规则兜底**：金额/日期/比例这类数值论元有强规律，模型没抽到时用正则补，并标 `source="regex"`。
2. **三类校验**：论元必须在原文（span 校验）/ 角色必须属于该事件类型（schema 校验）/ 去重。
3. **needs_review**：置信度低、无事件、缺核心角色、枚举角色取值不合法 → 交人工复核。
4. **篇章合成**：切句后把碎片**合并到接近训练分布的长度**（80~320 字），再把句子坐标换成全文坐标。

**⚠ 两个实测踩坑（也是最好的教学素材）**
- 切句若按标点硬切成 15~30 字碎片，模型输入分布与训练（平均 164 字）不符 → 事件从 6 个掉到 **0 个**。
- 「置信度」**不能**用整条序列概率连乘（68 个 token、每 token 0.93 自信，连乘只剩 0.007）→
  要用**按 token 平均概率**，否则所有句子都会被判 needs_review。

**切句契约（`split_sentences`，部署时最容易掉点的一环）**
- 先按 `。！？；` 与换行切成最小单元，再把过短单元**合并到 80~320 字**（训练句平均 164 字、中位 161），
  碎片化输入是「一篇 6 个事件抽出 0 个」的第一大原因；
- 返回 `[(字符偏移, 片段)]`，且必须满足 `text[off:off+len(seg)] == seg` —— 篇章级 span 的全文坐标全靠这个 offset 换算；
- ⚠ 实现坑（已修，2026-11-19）：旧版用 `start += len(seg)` 累加偏移，连续标点/空行不匹配正则 → 偏移漏加，
  81% 的 dev_docs 出现漂移（最大 1249 字）。现在改成「只记区间 + `text[s:e]` 切片」，实测 985 篇 **0 漂移**。

**实测（3 篇 dev_docs，金标共 18 个事件 → 抽出 8 个）**：天舟文化 3 / 6（conf 0.96-0.98）、恒大回购 **5** / 6、
北京市监局约谈 **0** / 6（只吐 `I-ARG`、无触发词 → 按「无触发词不成事件」整篇转人工，`needs_review=true`）。

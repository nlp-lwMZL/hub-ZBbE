### 1.3 指标定义（对应 `common/metrics.py`）

- **overall P/R/F1**：按 `(start, end, label)` 三元组的 span 集合逐文档计算，span 起点、终点、标签三者完全一致才算命中；为 micro 汇总（`compute_metrics`）。
- **trigger F1 / arg F1**：同上，分别在触发词 span 子集、参数 span 子集上计算。
- **type acc / macroF1 / microF1**：事件类型推断的准确率与 F1（`compute_type_metrics`）。
- **event exact**：单文档比对，要求**类型相同 + 触发词 span 完全相同 + 参数 span 集合完全相同**，三者同时满足才计为正确（`compute_event_exact_match`）。该指标为严格全匹配，任一槽位漏抽或多抽即判错。

### 1.4 评估集差异（重要，禁止跨节横比）

| 实验组 | 评估集 | 所在章节 |
|---|---|---|
| BiLSTM 系列 | val 全量 3,514 条 | 第 3、4 节 |
| RoBERTa 系列 | val 全量 3,514 条 | 第 5 节 |
| 生成式（LoRA / API） | val 分层抽样 99 条（seed=43，每类上限 15） | 第 6 节 |

生成式评估集按类别分层，稀有类占比被人为放大，与判别式的 3,514 条分布不同，**两组数字不可直接比较**。本报告仅在各自评估集内做同集对比。

## 3. 实验一：BiLSTM 上 CRF 与解码期硬约束的消融

数据来源：4 个 `extract/output/bilstm/abl_*/val_report.json`。

| 配置 | event exact | overall F1 | trigger F1 | arg F1 | type acc | type macroF1 |
|---|---|---|---|---|---|---|
| CRF ✓ 约束 ✓（基线） | 2330/3514 = 0.6631 | 0.9400 | 0.8013 | 0.9646 | 0.9599 | 0.4162 |
| CRF ✓ 约束 ✗ | 2325/3514 = 0.6616 | 0.9371 | 0.8004 | 0.9613 | 0.9599 | 0.4155 |
| CRF ✗ 约束 ✓ | 1813/3514 = 0.5159 | 0.9012 | 0.6939 | 0.9385 | 0.9044 | 0.3143 |
| CRF ✗ 约束 ✗ | 1702/3514 = 0.4843 | 0.8806 | 0.6890 | 0.9146 | 0.9075 | 0.3148 |

### 差值（百分点，正为提升）

| 变化 | event exact | overall F1 | type macroF1 |
|---|---|---|---|
| 去掉 CRF（有约束条件下） | −14.72 | −3.88 | −10.19 |
| 去掉 CRF（无约束条件下） | −17.73 | −5.65 | −10.07 |
| 去掉硬约束（有 CRF 条件下） | −0.15 | −0.29 | −0.07 |
| 去掉硬约束（无 CRF 条件下） | −3.16 | −2.06 | +0.05 |

### 可复核的支撑事实

1. **硬约束不参与训练**：`abl_nocrf_constr` 与 `abl_nocrf_noconstr` 两个 run 的 `train_loss` 均为 0.504119，`val_loss` 均为 0.022270，且日志中 38 个记录点的 loss 逐点相同（见各 run 的 history 与损失曲线）。据此可判断两组训练过程一致、差异仅来自解码，「约束作用于解码期」由数据直接支持。
2. **可复现性**：`abl_baseline_1ep` 与 run #5 的 epoch 1 各项 loss 完全相同（train_loss 205.91911760788423，val_loss 4.310285829901695，val_f1 0.939993），说明固定 seed 下同配置训练结果一致。
3. **CRF 与 Softmax 的 loss 不可跨模型比较**：CRF 的 train_loss 量级为 205.92（#1、#2）与 41.34/1.71（RoBERTa #7），Softmax 为 0.504（#3、#4）与 0.794/0.696（#6）。本报告不以 loss 大小做横向对比。

### 训练损失曲线

数据来源：4 个 run 的日志中 `step N/1947 | batch_loss=…` 行（`common/trainer.py` 第 98 行），日志每 50 step 记录一次，每个 run 38 个点，值为**该 step 单个 batch 的 loss 原值**。两组 loss 定义不同：CRF 组为 batch 内 NLL 求和（`CRF.neg_log_likelihood`），Softmax 组为逐 token 交叉熵均值（`F.cross_entropy` 默认 `reduction="mean"`）。因此两幅子图的量级差（10³ 与 10⁰）部分源自 loss 定义本身，不能解读为模型优劣，故采用对数轴并分为两幅子图。

![BiLSTM 消融损失曲线](figures/fig2_bilstm_ablation_loss.png)

图中「约束开」与「约束关」两条曲线**逐点重合**（粗实线为「开」，细虚线为「关」）。这与本节「可复核的支撑事实」第 1 条一致：两组训练过程数值完全相同，差异只出现在解码阶段，因此训练损失曲线必然重合——这是对该结论的图形化佐证，而非新的独立证据。两条曲线的起止值分别为：CRF 组 2,814.60 → 4.78，Softmax 组 6.72 → 0.02（首个记录点为 step 50，末个为 step 1900）。

## 5. 实验三：编码器替换（RoBERTa）

数据来源：`roberta/20261125_123710_.../val_report.json`、`roberta/20261125_183947_.../val_report.json`。

共同设置（取自运行日志第 6 行）：`pretrain_dir=pretrain_models/chinese-roberta-wwm-ext, max_len=512, stride=384, batch_size=16, grad_accum_steps=1, lr=2e-5, head_lr_mult=5.0, layer_lr_decay=0.95, weight_decay=0.01, warmup_ratio=0.1, epochs=2, monitor=event_exact, seed=42, device=cpu, amp=True`。数据：训练 28,150 条切块为 62,285 块，验证 3,514 条切块为 6,377 块；评估汇总回 3,514 篇文档。

| 配置 | event exact | overall F1 | trigger F1 | arg F1 | type acc | type macroF1 |
|---|---|---|---|---|---|---|
| RoBERTa + Softmax（LS=0.1，grad_clip=1.0） | 3177/3514 = 0.9041 | 0.9791 | 0.9855 | 0.9780 | 0.9852 | 0.6303 |

### 训练损失曲线

数据来源：两 run 日志的 `step N | loss=…` 行（每 50 step 记录，各 154 点）。该记录的值为**自本 epoch 起始的累计平均**（`extract/roberta/train.py` 第 691–694 行 `running / n_micro`），不是当前 step 的瞬时值。日志中 step 每 epoch 从 1 重新计数，图中横轴已换算为累计 step，竖虚线为 epoch 2 起点。

- LoRA − 零样本：event exact **+19.19pt**，overall F1 **+27.75pt**。

单样本版相对零样本的 event exact 曾出现下降（10 → 8，−2.02pt）后，在追加强制规则（日期类与说明类字段必填、触发词须逐字摘录且不得填事件类型名、区分离任/变更/增聘三类事件）后回升至 14。

**速度数据不引用**：`experiments.csv` 中零样本行 `sec_per_item=1.5` 含断点续跑（部分样本复用了已保存的输出），与实际单条耗时不可比；其余两行为 7.8 / 8.2 秒/条。

## 7. 运行速率与延迟

环境：单机 CPU。`torch 2.6.0+cpu`、`torch.cuda.is_available()=False`、逻辑核 24、PyTorch 线程数 12。BiLSTM 与 RoBERTa 配置 `device=auto`（本机无 CUDA，实际解析为 CPU），LoRA 配置 `device=cpu`。所有耗时均取自日志 `Epoch` 行、日志 `step` 行与 `val_report.json` 的 `stats`，未做外推。

计时口径：日志的 `step` 计时**每个 epoch 重置**；`Epoch` 行的秒数为该 epoch 的「训练 + 评估」总时长。因此 7.1 的「训练秒」= 该 epoch 最后一条 step 记录的累计值，7.2 的「评估耗时」= Epoch 总时长 − 训练秒。

| BiLSTM+CRF+约束 | 28,150 | 1,947 | 32 | 0.721 | 20.05 | 1,403.7s | 25.0 min |

## 8. 报告限定条件

1. **单一随机种子**：所有训练 run 的 `seed` 均为 42，每个配置只训练一次，无重复实验，因此表中差值仅为本次观测值，**不构成显著性结论**。生成式评估集的分层抽样种子为 43（`seed+1`），LoRA 与三次 API 评估使用的是同一批 99 条样本。
2. **未使用测试集**：全部指标为验证集结果，`extract/output/` 下无 test 评估报告。
3. **跨节不可比**：第 6 节的 99 条评估集为分层抽样，稀有类占比高于全集；与第 3–5 节的 3,514 条不支持直接横向比较。
4. **第 5 节的混淆变量**：Softmax 与 CRF 两个 run 的 `label_smoothing`、`grad_clip` 不同（见 5 节），差值不能单独归因于解码头。
5. **稀有类样本量过小**：`基金经理助理离任`（7）、`基金经理助理变更`（1）、`其他人事变动`（1）三类，即使全对也仅影响 exact 0.20pt / 0.03pt / 0.03pt，其 0 命中不宜直接解释为模型缺陷。
6. **本报告不对上述差异给出去因解释**。例如「CRF 主要在稀有类上生效」「4B 提示词已到能力上限」等判断，需以机制实验或更多重复实验验证后才能成立，此处仅记录观测到的计数差异。

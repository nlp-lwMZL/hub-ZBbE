# 题 1：因果掩码与 Transformer 结构

## 1.1 `nn.TransformerEncoderLayer` 一个 block 里有什么

```python
nn.TransformerEncoderLayer(d_model, nhead, dim_feedforward,
                           activation="gelu", norm_first=True, batch_first=True)
```

**问：一个 block 里包含哪些子层？`norm_first=True` 是 Pre-LN 还是 Post-LN？`dim_feedforward=4*d_model` 这个 4 倍是从哪来的？**

### 答

**1. 一个 block 包含的子层**

- **MHA 多头注意力**（Multi-Head Attention）
- **FFN 前馈网络**（Feed-Forward Network）
- 每个子层外面各配一组**残差连接 + LayerNorm 归一化**：`x + Sublayer(x)` 之后再做归一化（或在归一化之后再进子层，见下）。

即一个 block 共两个"残差 + 归一化"单元：一个包着 MHA，一个包着 FFN。

**2. `norm_first=True` 是 Pre-LN**

```
Pre-LN（norm_first=True）:   x + MHA(LN(x))     →   x + FFN(LN(x))
Post-LN（norm_first=False）: LN(x + MHA(x))     →   LN(x + FFN(x))
```

Pre-LN 把归一化放在子层**之前**、残差分支保持恒等通路，梯度可以无损地沿残差边回传，深层堆叠更稳定；Post-LN 是原始论文写法，训练前期通常需要 warmup。本项目代码使用 `norm_first=True`。

**3. `dim_feedforward = 4 × d_model` 的 4 倍来自原始论文**

这个 4 倍是《Attention Is All You Need》给出的超参数（d_model=512、FFN 隐层 2048）。FFN 的结构是"升维 → 激活 → 降维"（`d_model → 4·d_model → d_model`），作用是**先把特征升到更高维的空间丰富表达，再压回原维度**。本实现沿用了这一比例。

## 1.2 `generate_square_subsequent_mask(4)` 是什么

### 运行结果

```python
import torch
m = torch.nn.Transformer.generate_square_subsequent_mask(4)
print(m)
```

```
tensor([[  0., -inf, -inf, -inf],
        [  0.,   0., -inf, -inf],
        [  0.,   0.,   0., -inf],
        [  0.,   0.,   0.,   0.]])
```

shape = `(4, 4)`，dtype = `torch.float32`。

### 形状说明（先纠正一个常见口误）

严格说被置成 `-inf` 的是**上三角（主对角线右上方）**，即 `j > i` 的位置；主对角线本身和下三角（`j <= i`，含自己）是 `0`。视觉上那块三角形位于矩阵右上，不是左上。

| 行列关系 | 含义 | 取值 |
|---|---|---|
| `j > i`（未来） | 第 i 个位置去看第 j 个位置，属于偷看未来 | `-inf` |
| `j <= i`（过去 / 当前） | 看自己或看上文，合法 | `0` |

以第 2 行（i=1，处理第 2 个字）为例：允许看位置 0、1（自己和前文），屏蔽位置 2、3（后面的字）。

### 为什么是 -inf 而不是 1

这个矩阵不是"布尔屏蔽表"，而是**直接加到注意力打分上的加性掩码**（additive mask）。Transformer 内部计算是：

```
Attention(Q, K, V) = softmax(QKᵀ / √d + mask) · V
```

关键在于 `softmax` 的性质：`exp(-inf) = 0`，而 `exp(0) = 1`。

- 合法位置 `+0`：不改变原始打分，`exp` 后保留原权重。
- 未来位置 `+-inf`：`exp(-inf) → 0`，softmax 权重被精确压到 0，**未来位置彻底不参与加权求和**。
- 若误用 `1` 作屏蔽值：`exp(0+1)=e≈2.718` 反而给未来位置**加权**，屏蔽完全失效——这正是上一组实验 `--no-mask` 全位置 PPL 掉到 1.19 的原因。

用 `-inf` 而非一个很大的负数（如 `-1e9`）是因为 `-inf` 是数学上的精确零概率，不依赖量级估计，也不会因数值过大在 fp16 下溢出成 `nan`。

### 实测：掩码如何改变 softmax

```python
torch.manual_seed(0)                                         # 固定随机打分，保证可复现
scores = torch.randn(4, 4)                                   # 模拟 QKᵀ/√d
masked = scores.masked_fill(mask == float('-inf'), float('-inf'))
probs  = torch.softmax(masked, dim=-1)
```

```
原始打分 scores:
tensor([[-1.1258, -1.1524, -0.2506, -0.4339],
        [ 0.8487,  0.6920, -0.3160, -2.1152],
        [ 0.3223, -1.2633,  0.3500,  0.3081],
        [ 0.1198,  1.2377,  1.1168, -0.2473]])

加上 mask 后:
tensor([[-1.1258,    -inf,    -inf,    -inf],
        [ 0.8487,  0.6920,    -inf,    -inf],
        [ 0.3223, -1.2633,  0.3500,    -inf],
        [ 0.1198,  1.2377,  1.1168, -0.2473]])

softmax 后（每行和为 1，未来位置权重恒为 0）:
tensor([[1.0000, 0.0000, 0.0000, 0.0000],
        [0.5391, 0.4609, 0.0000, 0.0000],
        [0.4478, 0.0917, 0.4604, 0.0000],
        [0.1340, 0.4099, 0.3632, 0.0928]])

每行权重和: tensor([1., 1., 1., 1.])
exp(-inf)  = tensor(0.)
```

可以看到 `scores` 第 1 行有 4 个合法候选取值，被 `-inf` 抹掉位置 1~3 后只剩位置 0 可看，权重直接被归一化成 1.0；第 2 行只剩位置 0、1 两个候选，原来的两个未来位置权重精确归零。**这就是"因果"（causal）的实现方式：每个位置只能看到 `<=` 自己的 token。**

# 题 2：验证掩码真的生效（扰动末位 token 实验）

### 实验设计与耗时

纯前向推理，**不需要训练，秒级完成**。用已训练好的 `tf_full_80w.pt` 真实权重（同一套权重只切换 `causal` 开关，保证除掩码外无任何差异）：

1. 取语料首行前 10 个字 `"女朋友和我打冷战，怎"` 作为输入，前向得到每个位置的 logits；
2. **只把最后一个 token** 从 `怎` 改成 `，`，其余 9 个位置完全不动，再前向一次；
3. 逐位置比较两次 logits 的最大绝对变化。

若因果掩码生效，前 9 个位置**看不到**末位，输出必须**逐位精确为 0**；若抽掉掩码，末位的改动会通过注意力扩散到全部位置。

### 核心代码

```python
m.eval()                                    # 关键：eval 关掉 dropout，否则变化量里混入随机噪声
with torch.no_grad():
    a = m(x)                                # 原始输入
    x2 = x.clone(); x2[0, -1] = other_id    # 只扰动最后一个 token
    b = m(x2)
diff = (b - a).abs().amax(-1)[0]            # 每个位置上 logits 的最大变化
```

### 运行结果

```
输入: 女朋友和我打冷战，怎   末位字: 怎 -> 改成: ，

有掩码 各位置最大变化:
tensor([0.0000e+00, 0.0000e+00, 0.0000e+00, 0.0000e+00, 0.0000e+00,
        0.0000e+00, 0.0000e+00, 0.0000e+00, 0.0000e+00, 1.1451e+01])

无掩码 各位置最大变化:
tensor([2.6851e+00, 1.2546e+00, 4.5933e+00, 3.1428e+00, 2.2350e+00,
        2.9097e+00, 4.9018e+00, 5.2033e+00, 1.8016e+00, 1.1418e+01])
```

### 结论

| 条件 | 前 9 个位置的变化 | 末位（第 10 个）的变化 |
|---|---|---|
| **有因果掩码** | **全部精确 0**（9/9 为 0.0000e+00） | 1.1451e+01 |
| **无因果掩码** | 全部非零（9/9），最大 5.2033e+00 | 1.1418e+01 |

- 有掩码时前 9 位是**浮点意义上的精确 0**，不是"接近 0"——因为末位 token 根本没进入这些位置的注意力求和，计算图和算术路径完全相同，所以逐位 bit 级一致。这比"变化量很小"更严格地证明了因果性。
- 无掩码时 9 个位置全都被末位污染，平均抖动 3 个 logits 量级，说明每个位置都在 attend 未来 token。
- 末位自身在两种情况下都会变（它是被改动的那个 token 本身），这属于正常现象，恰好构成对照组。

这也从机制上解释了题 3 的异常数字：`--no-mask` 时模型能直接看到"下一个字"，于是全位置 PPL 被压到 1.19（抄答案）；末位看不到未来，PPL 才是真实的 267.73。

> 注：`m.eval()` 不可省略。若在 `train()` 模式下做这个实验，dropout 会随机置零神经元，前 9 位的差异将不再为 0，实验会失效。

> 以上两题的验证代码已固化到 [language_mode_test.py](file:///C:/Users/YiGao/AI_Learning/八斗AI课程/第四周%20语言模型/循环神经网络语言模型/language_mode_test.py)，运行 `python language_mode_test.py` 可一键复现（含断言校验）。

# 题 3：字符级语言模型对照实验报告

## 实验目标

在同一份语料、同一套切分、同一个验证集下，控制参数量对齐在 ±10% 以内，对比：

1. Transformer（因果掩码 + 位置编码）
2. Transformer（仅因果掩码，`--no-pos`）
3. Transformer（仅位置编码，`--no-mask`）
4. LSTM 对照

## 统一实验设置

| 项目 | 配置 |
|---|---|
| 语料 | corpus_train.txt，取前 **800,000 字** |
| 词表 | V = 4000（按 80 万字语料重建 vocab.csv） |
| 切分方式 | 滑窗 `stride=64`，窗宽 `max_length=64` |
| 训练集 | 761,446 字 / 12,729 样本 |
| 验证集 | 38,554 字 / 646 样本（尾部独立字符流，无窗口泄漏） |
| 公共超参 | seed=42、batch_size=256、lr=1e-3、dropout=0.3、d_model=192、num_heads=4、epochs=6 |
| 运行环境 | torch 2.6.0+cpu，Python 3.12（conda env: py312） |

### 参数量对齐方案

- **Transformer**：4 层 + `--tie`（输入/输出 embedding 权重共享）→ **2,560,128** 参数
- **LSTM**：2 层 + `--lstm-hidden 234` → **2,560,816** 参数
- 两者偏差 **0.03%**，远优于 ±10% 要求

估算公式：LSTM ≈ 784,288 + 12H² + 4,784H（H=234）

## 运行命令

```powershell

python language_mode.py --model transformer --tie --max_chars 800000 --stride 64 --epochs 6 --dropout 0.3 --save tf_full_80w.pt

# 3. Transformer 仅位置编码（无因果掩码）
python language_mode.py --model transformer --tie --no-mask --max_chars 800000 --stride 64 --epochs 6 --dropout 0.3 --save tf_nomask_80w.pt

# 4. LSTM 对照（2 层，hidden=234 对齐参数量）
python language_mode.py --model lstm --num-layers 2 --lstm-hidden 234 --max_chars 800000 --stride 64 --epochs 6 --dropout 0.3 --save lstm_80w.pt
```

## 结论

1. **因果掩码是必需品**
   去掉因果掩码后，全位置 PPL 崩至 1.19。原因是注意力可以直接 attend 到窗口内的下一个字，等于抄答案——这不是学习，而是信息泄漏。末位 PPL 267.73（窗口末位看不到未来）才暴露真实水平，比完整版差约 2.9 倍。说明模型把注意力全用在抄近路上，没有学到语言规律。

2. **位置编码在本实验条件下收益甚微**
   仅因果掩码（NoPE）的 95.01 与完整版 94.05 几乎持平，末位 PPL 甚至略优（69.36 vs 69.72）。原因是因果掩码使每个位置可见的上下文长度各不相同，本身就已经携带弱位置信号（NoPE 效应）。在字符级、64 字短窗、6 轮以内训练的条件下，额外叠加学习式位置编码带来的收益几乎可以忽略。

3. **同参数量下 Transformer 显著优于 LSTM**
   全位置 PPL 94.05 vs 269.95，效果差距约 2.9 倍。且 LSTM 到第 6 轮仍在大幅下降（534 → 270），收敛明显更慢，尚未达到性能平台。代价是 CPU 吞吐低约 46%（15,732 vs 29,386 tok/s），符合"注意力并行利用率低于 LSTM 单步递推"的预期。

4. **参数量对齐达标**
   四组参数量偏差最大仅 0.51%，全部远优于 ±10% 要求，容量混杂因素已被排除，上述 PPL 差异可归因于架构与组件差异。

## 局限与后续建议

- 两组模型均未完全收敛（PPL 仍在下降），当前结论是"6 轮预算下"的相对表现，延长训练轮次后差距可能收窄。
- 各实验仅用单一 seed（42），建议多 seed 取平均以获得更稳健的结论。
- 泄漏实验（无掩码）应始终同时报告末位 PPL，只看全位置 PPL 会得出完全错误的结论。
- 位置编码的收益随序列长度增长而增大，可加长 `max_length`（如 128/256）后重跑 NoPE 对照验证。

- 模型未完全收敛（全语料 6 轮后 PPL 仍在下降），继续延长训练生成质量还会改善。

# 题 5：概念三问

## 5.1 为什么自回归语言模型**必须**有因果掩码？

因为自回归语言模型是通过前面的字预测下一个字，所以它只能看到过去和现在的字，不能看到未来的字。看到了就相当于模型作弊抄答案，实际上没有学习到任何规律。

所以必须通过因果掩码将注意力矩阵中上三角的内容 mask 为 `-inf`，这样在 softmax 时这些被遮掩的值就会被计算为 0，彻底脱离注意力计算，不会造成泄露。

> 本报告的实验证据：题 1.2（掩码矩阵与 softmax 机制）、题 2（扰动末位 token，前 9 位变化精确为 0）、题 6（去掉掩码后 PPL 崩到 1.08 的假象）。

## 5.2 位置编码去掉之后，模型丢了什么信息？PPL 掉多少？

在自注意力计算中，`Q·Kᵀ` 本身并不关心词的语序——同一组字无论怎么排列，两两点积的结果集合是一样的。所以如果去掉位置编码，模型会**丢失字与字之间的语序关系**，只剩"袋装字符"信息。

全语料下的实测变化（题 3）：

| 口径 | 完整版 | 去掉位置编码（NoPE） | 变化 |
|---|---|---|---|
| 全位置 PPL | 33.62 | 38.31 | +4.69（**变差 12.3%**） |
| 末位 PPL | 32.55 | 39.29 | +6.74（变差 17.2%） |

注意因果掩码本身会携带弱位置信号（每个位置可见的上下文长度不同），所以 NoPE 模型并非完全没有位置信息，PPL 不会崩掉，但稳定地差一截。

## 5.3 参数量对齐时 Transformer 和 LSTM 谁更强？为什么 Transformer 算得更快（并行的来源）？

**谁更强**：参数量对齐（均约 2.56M，偏差 0.03%）的情况下，**Transformer 的 PPL 更低**——全语料 6 轮，Transformer 33.62 vs LSTM 49.58（好 1.48 倍）；80 万字时差距更大（94.05 vs 269.95，2.87 倍）。

**为什么 Transformer 能算得更快（并行的来源）**：

Transformer 的核心就是 MHA 和 FFN，这两个部分的计算过程**不存在 LSTM/RNN 那样的时间步前后依赖**（LSTM 的 `h_t` 必须等 `h_{t-1}` 算完，序列维度只能串行）。具体有两层并行：

1. **序列维度并行**：MHA 主要进行矩阵乘法和线性变换，Q/K/V 是由整个序列一次性拼成的大矩阵（矩阵大小取决于序列长度），所有位置的注意力打分在**一次矩阵乘法**中同时算出，不需要逐字递推。
2. **头的维度并行**：多头情况下，Q、K、V 可以按超参数"头数"沿特征方向切分成若干个小矩阵，各头的注意力计算互不依赖，可以并行执行。

FFN 部分同理：它对每个位置独立地做"升维 → 激活 → 降维"，本质上也是两次矩阵乘法（矩阵规模由升维超参 `dim_feedforward` 控制），所有位置可以一次性并行完成。

> 需要说明的是：这是"**每处理一个 token 的并行潜力**"，能否兑现取决于硬件。本实验在 CPU 上，注意力与多层矩阵乘法的并行利用率低，实测吞吐反而是 LSTM 更高（27,615 vs 15,758 tok/s，约 1.75 倍）；在 GPU 上矩阵乘法的并行优势才能充分释放，结论会反过来。

# 题 6：泄露实验 —— PPL 1.07 的假象

## 实验设置

与题 3 的完整版**唯一差异**是去掉因果掩码，其余全部相同：

```powershell
python language_mode.py --model transformer --tie --no-mask `
  --max_chars 800000 --stride 64 --epochs 6 --dropout 0.3 --seed 42 `
  --save tf_nomask_leak_80w.pt
```

- 语料 800,000 字 / 词表 V=4000 / 滑窗 stride=64
- 训练 761,446 字（12,729 样本），验证 38,554 字（646 样本）
- 参数量 2,560,128（与完整版完全一致）
- 单轮约 40~51 秒，6 轮总耗时 **约 4.3 分钟**

> 本次重训吞吐测得 19,784 tok/s，题 3 同配置测得 15,281 tok/s，差异来自机器负载波动，与模型无关。

## 逐轮指标：三者的走势完全背离

| 轮次 | 训练损失 | 训练 PPL | 验证全位置 PPL | 验证末位 PPL |
|---|---|---|---|---|
| 1 | 6.57796 | 719.07 | 452.31 | 406.64 |
| 2 | 5.92336 | 373.66 | 262.84 | 246.97 |
| 3 | 4.27976 | 72.22 | **8.83** | **942.48** ↑ |
| 4 | 1.52172 | 4.58 | 1.94 | 700.68 |
| 5 | 0.60587 | 1.83 | 1.31 | 309.98 |
| 6 | 0.32967 | 1.39 | **1.19** | **267.73** |

三个关键现象：

1. **训练损失一路暴跌**：6.58 → 0.33，训练 PPL 从 719 掉到 1.39，看起来是"训练极其成功"。
2. **全位置 PPL 同步崩到 1.19**：比完整版的 94.05 好了近 80 倍。
3. **末位 PPL 却在第 3 轮反向飙升**：从 246.97 冲到 942.48，之后才缓慢回落，6 轮结束仍高达 267.73。

第 3 轮是决定性证据：**同一轮次、同一模型，全位置 PPL 只有 8.83，末位 PPL 却高达 942.48，相差 107 倍，方向完全相反。**

## 为什么 "PPL 1.07" 是假象

### 1. 任务被改坏了，不是模型变强了

完整版的预测规则是：第 i 个位置只能看 `0..i` 的 token，要预测第 `i+1` 个字。

去掉掩码后，第 i 个位置可以 attend 到 `0..63` 的**全部** token，而它要预测的第 `i+1` 个字**就在这些可见 token 里**。

于是这个任务退化成**恒等复制**：把注意力权重全部压到"下一个位置的 token 上"，就能直接读出答案，不需要理解任何语义、语法或上下文。

```
正常任务:  看 [字0..字i]        → 预测 字(i+1)      需要真正建模语言
泄露任务:  看 [字0..字i, 字(i+1)] → 预测 字(i+1)    直接抄，loss 可无限趋近 0
```

### 2. PPL 的理论下限是 1，可以一直往下压

`PPL = exp(交叉熵)`，而交叉熵可以趋近 0，所以 **PPL 可以无限接近 1，但永远不可能低于 1**。

- PPL 1.19 意味着模型平均每个字只有 0.17 nats 的不确定性，几乎是"100% 确定下一个字"；
- 换成 1.07 就是 0.068 nats，比这更极端。

而自然语言本身有信息熵（中文单字熵大致在 4~9 bit，约合 3~6 nats）。完整版模型的 PPL 94.05 对应交叉熵 4.54 nats（约 6.55 bit），正好落在这一量级；而泄露模型的 0.17 nats 远低于任何真实语言的下限。**一个语言模型 PPL 越接近 1，越应该怀疑任务坏了，而不是模型强了。**

> 关于 1.07：这个数值取决于语料规模与训练步数。本题在 80 万字上 6 轮实测为 **1.19**；换成全语料（corpus_general，步数 ×7）后实测为 **1.08**，与题面所述的 1.07 吻合（见题 3 的全语料复跑，末位 PPL 同步从 267.73 降到 148.17）。换句话说，**数据越多、PPL 越贴近 1，这恰恰说明泄漏被学得更彻底，而不是效果更好。**

### 3. 末位 PPL 才是唯一可信的口径

窗口的**最后一个位置**（第 63 位）在因果意义上不存在"未来"，无论有没有掩码，它都必须靠真实上下文预测第 64 个字——**只有它没有资格抄答案**。

| 口径 | 泄露模型 | 完整版 | 差距 |
|---|---|---|---|
| 全位置 PPL | 1.19 | 94.05 | 好 79 倍（假） |
| 末位 PPL | 267.73 | 69.72 | **差 3.8 倍**（真） |

同一份权重，两个口径给出**方向相反**的结论。唯一合理的解释就是：全位置口径被污染了。

### 4. 生成结果当场露馅

```powershell
python language_mode.py --ckpt tf_nomask_leak_80w.pt --generate "今天天气" --n_chars 40
```

采样（T=0.8）与贪心（T=0.01）输出几乎一致，说明这不是采样噪声，而是模型的确定性策略：

```
采样: 今天天气天气气气天气天天气气天气气气气气气气天天气气气气天城天天天天气气气天天气气天天天
贪心: 今天天气天气气气天气天天气气天气气气气气气气天天气气气气天气天天天天气气气天天气气气天天
```

对照完整版同输入贪心输出：

```
完整版: 今天天气怎么样
        这个是什么意思
        这个是什么意思
        这个动漫画片
        这个是什么
```

- 泄露模型只会把输入里的"天气""气"反复复制，**完全没有语言能力**；
- 完整版能续出"今天天气怎么样"这种通顺句子，虽然随后也陷入重复，但至少学到了真实分布。

PPL 1.19 的"优秀"模型，生成时连一个像样的短句都产不出来——**这就是假象最直接的证据**。

## 全语料复跑（corpus_general，6 轮）

同一实验在全语料（5,626,360 字，89,453 样本，步数 ×7）上重跑，权重文件 `tf_nomask_general.pt`。

### 三者走势（全语料）

| 轮次 | 训练损失 | 训练 PPL | 全位置 PPL | 末位 PPL |
|---|---|---|---|---|
| 1 | 2.78402 | 16.18 | 1.15 | 314.47 |
| 2 | 0.16660 | 1.18 | 1.10 | 258.62 |
| 3 | 0.13971 | 1.15 | 1.09 | 219.05 |
| 4 | 0.13250 | 1.14 | 1.09 | 194.82 |
| 5 | 0.12772 | 1.14 | 1.08 | 165.62 |
| 6 | 0.12257 | 1.13 | **1.08** | **148.17** |

与 80 万字版的三点差异：

1. **泄漏收敛快得多**：80 万字时第 3 轮才突然崩到 8.83，全语料**第 1 轮就直接到 1.15**——数据越多，模型越快发现"抄下一个字"这条捷径。训练损失第 1 轮只有 2.78（80 万字同期 6.58）。
2. **全位置 PPL 更低**：1.19 → **1.08**，与题面所述的 "1.07" 吻合，确认该数值出自全语料配置。数据越多，假指标越逼近理论下限 1.0。
3. **末位 PPL 反而改善**：267.73 → 148.17。原因是末位不能抄答案，只能真实学习，而全语料让步数 ×7，真实能力确实提升了——但它仍比同语料完整版的 32.55 差 **4.6 倍**，泄漏对真实能力的损害依旧。

### 生成输出（全语料）

```

贪心: 今天天气天气天气天气天天天气天气天气天气天天天气天气天气天天气气天气气气天气天气气天天天
```

**与 80 万字版几乎一模一样**——数据量 ×7 后复制策略分毫未改。对照同语料完整版贪心输出：

```
完整版(全语料): 今天天气怎么样？
              怎么样才能让自己变大
              怎样才能让自己变得快速变大
              怎样才能让自己变小
```

一边是 PPL 1.08 却只会复制输入，一边是 PPL 33.62 却能连续写出四句通顺中文。**全语料把"指标与能力的背离"拉到了极限，这是本题最有说服力的一组对照。**

## 结论

1. **PPL 只有在评估口径与训练口径一致、且不存在信息泄漏时才有意义**。去掉因果掩码后，模型学到的是"复制"，不是"语言"。
2. **训练 loss、全位置 PPL、末位 PPL 三者必须一起看**。只报全位置 PPL 会把一个废模型评为最优模型；本题中三者的背离（全位置崩到 1.19 的同时末位冲到 942）就是最明确的报警信号。
3. **PPL 越接近 1 越可疑**。真实语言有熵，正常模型的 PPL 不会低于语料自身的单字熵量级。
4. **对训练和验证都要掩码**。本实验的泄漏发生在训练和验证两侧（同一 `USE_CAUSAL` 开关），所以验证集也没有拦住它——验证集只能发现过拟合，发现不了任务定义错误。
5. **（全语料补充）加数据只会强化假象，不会修复它**。数据 ×7 后全位置 PPL 从 1.19 降到 1.08、泄漏第 1 轮就收敛，而生成行为零改善。发现泄漏不能靠"再加点数据看看"，只能靠口径检查（末位 PPL）与生成抽检。

> 工程建议：把"末位 PPL"和"生成抽样"作为 PPL 的固定伴随指标，任何一次 PPL 异常低时先查掩码，而不是先庆祝。

# 题 7：位置编码消融（L=64 → L=256）

## 实验设置

同一份 80 万字语料、`stride=64`、6 轮、dropout 0.3，只动两个变量：位置编码有无、序列长度。

> 参数名对照：题面 `--seq_len` 对应脚本的 `--max-length`。

| 实验 | 命令 |
|---|---|
| L=64 完整版 | 题 3 已有结果（`tf_full_80w.pt`） |
| L=64 NoPE | 题 3 已有结果（`tf_nopos_80w.pt`） |
| L=256 完整版 | `--max-length 256 --stride 64 --save tf_L256_80w.pt` |
| L=256 NoPE | `--max-length 256 --stride 64 --no-pos --save tf_L256_nopos_80w.pt` |

关键设计：**L 变化时保持 stride=64 不变**。窗口数 = 字符数/stride，所以两组 L=256 的样本数仍是 12,726（与 L=64 的 12,729 几乎相同），梯度更新次数、数据顺序、验证集口径完全一致；唯一变化是每条样本的 token 数（63 → 255，4.05 倍）。

## 结果

| 实验 | 参数量 | 全位置 PPL | 末位 PPL | 吞吐 tok/s | 单轮耗时 |
|---|---|---|---|---|---|
| L=64 完整版 | 2,560,128 | **94.05** | 69.72 | 15,732 | 50 s |
| L=64 NoPE | 2,547,840 | 95.01 | 69.36 | 16,272 | 49 s |
| L=256 完整版 | 2,596,992 | 96.64 | 72.47 | 10,619 | 305 s |
| L=256 NoPE | 2,547,840 | **93.45** | 71.92 | 10,729 | 303 s |

### 位置编码的差距：没有被放大，反而反转

| 序列长度 | 完整版 − NoPE | 相对差 | 谁更好 |
|---|---|---|---|
| L=64 | −0.96（94.05 vs 95.01） | 1.0% | 完整版略好 |
| L=256 | +3.19（96.64 vs 93.45） | 3.4% | **NoPE 更好** |

- 绝对差距确实从 0.96 拉大到 3.19（3.3 倍），但**符号变了**：L=64 时完整版略优，L=256 时反而是 NoPE 更优。
- 因此**不能得出"序列越长位置编码越重要"的结论**。更准确的描述是：位置编码在两个长度下都不是决定性因素，差异始终在 1%~3% 量级，且方向不稳定。

### 为什么 L=256 时 NoPE 反而赢

1. **两个长度都远未收敛**。6 轮结束时 PPL 仍在明显下降（L=256 完整版第 5 轮 114.92 → 第 6 轮 96.64），此时 1%~3% 的差异完全落在训练噪声与初始化差异范围内，单一 seed 不足以下结论。
2. **完整版多出的参数是位置编码本身**（256×192 = +49,152，占 1.9%），且 `--tie` 要求 `std=0.02` 小方差初始化，位置表要覆盖 256 个位置，起步收敛更慢；短训练预算下这部分参数是负担。
3. **NoPE 在长窗口下更有优势**。窗口从 64 拉到 256 后，可见内容大幅增加，注意力可以完全靠内容寻址区分 token；此时强加绝对位置编码的必要性进一步下降。

### 顺带观察：加长序列本身在本预算内没有收益

| 配置 | L=64 | L=256 | 变化 |
|---|---|---|---|
| 完整版 | 94.05 | 96.64 | 差 2.8% |
| NoPE | 95.01 | 93.45 | 好 1.6% |

窗口拉长 4 倍、单轮算力约 6 倍，PPL 却基本原地踏步。说明**在 6 轮预算下，"看得更远"不是瓶颈，训练不充分才是**。

## 结论

1. 位置编码在本任务（字符级、2.5M 参数、6 轮、80 万字）下**始终是次要因素**，去掉它 PPL 变化不到 3.4%。
2. **"序列越长位置编码越重要"这一假设未被复现**，反而观察到符号反转；更合理的解释是训练预算不足导致的噪声，而非真实的结构性规律。
   > 补充（由题 3 的全语料复跑验证）：在 L=64 下把训练步数从 12,729 提到 89,453 后，完整版与 NoPE 的差距从 1.0% 扩大到 **12.3%**（33.62 vs 38.31）。这说明位置编码的收益**随数据/步数增加而显现**，而不是随序列长度增加而显现——本节的符号反转确实如推测那样，是欠训练造成的噪声。
3. **CPU 上拉长序列的代价很高**：L=256 每 token 吞吐从 15,732 降到 10,619（−32%），单轮耗时从 50 秒涨到 305 秒（6.1 倍，其中 4.05 倍来自 token 数、1.3 倍来自 O(L²) 注意力）。
4. 若要严肃验证这一假设，需要：多 seed 平均、充分训练至收敛（至少 20~30 轮）、并固定 token 预算而非固定轮数。

# 题 8：规模/长度实验

## 实验设置

> 参数名对照：题面 `--layers` 对应脚本的 `--num-layers`。

| 实验 | 命令要点 | 参数量 |
|---|---|---|
| 基线 4 层 L=64 | 题 3 完整版 | 2,560,128 |
| 加深 8 层 L=64 | `--num-layers 8 --max-length 64 --save tf_L8_80w.pt` | 4,339,584 |
| 加长 4 层 L=256 | 题 7 的 `tf_L256_80w.pt` | 2,596,992 |

关于"显存"：当前环境是 `torch 2.6.0+cpu`，**没有显存，只有内存**。8 层模型参数约 17 MB，L=256 的窗口张量约 26 MB，均无压力；真正的瓶颈是 CPU 算力。

## 结果

| 实验 | 参数量 | 相对基线 | 全位置 PPL | 末位 PPL | 吞吐 tok/s | 单轮 |
|---|---|---|---|---|---|---|
| 4 层 L=64（基线） | 2,560,128 | — | **94.05** | 69.72 | **15,732** | 50 s |
| **8 层 L=64** | 4,339,584 | +69.5% | **120.51** | 91.00 | 8,549 | 94 s |
| 4 层 L=256 | 2,596,992 | +1.4% | 96.64 | 72.47 | 10,619 | 305 s |

### 深化（8 层）：参数 +69.5%，效果 −28%，吞吐 −46%

- PPL 从 94.05 恶化到 120.51（差 28.1%），末位 PPL 从 69.72 恶化到 91.00（差 30.5%）。
- 吞吐从 15,732 降到 8,549（−45.7%），单轮从 50 秒涨到 94 秒。
- **性价比为负**：多花 69.5% 参数和 88% 时间，换来更差的效果。

### 原因是欠训练，不是"规模定律失效"

逐轮对比可以看出 8 层是**起点更差、但仍在快速下降**：

| 轮次 | 4 层 PPL | 8 层 PPL |
|---|---|---|
| 1 | 467.99 | 542.65 |
| 2 | 325.82 | 373.19 |
| 3 | 217.90 | 289.13 |
| 4 | 154.77 | 211.73 |
| 5 | 116.15 | 158.57 |
| 6 | 94.05 | 120.51 |

- 8 层第 6 轮相对第 5 轮下降 **24%**（158.57 → 120.51），4 层只下降 19%（116.15 → 94.05）。
- 深层网络更难优化：梯度要穿过更多层，`lr=1e-3` 无 warmup、无梯度裁剪、6 轮预算，训练量远不足以让 8 层收敛。
- 第 1 轮 8 层就比 4 层差（542.65 vs 467.99），说明瓶颈在优化难度，不是表达能力。

### 加长（L=256）：同样没有收益

PPL 96.64（比基线差 2.8%），吞吐 −32%，单轮成本 6.1 倍。原因同上：6 轮预算内"看得更远"不是瓶颈。

## 结论

1. **在本实验的预算（6 轮、80 万字、CPU、lr=1e-3）下，单纯加深或加长都没有收益，反而变差**。这不是规模定律失效，而是训练预算被撑爆：更深更长的模型需要显著更多的轮次才能收敛。
2. **参数量的收益有前提**：只有在训练轮次、学习率调度、warmup 等配套跟得上时，增加容量才会转化为更低的 PPL。6 轮预算下 4 层 2.56M 是最优性价比点。
3. **吞吐与容量的权衡很清楚**：8 层吞吐 −46%、L=256 吞吐 −32%，而 CPU 上没有并行加速余地，继续加大规模的时间成本会快速失控（8 层全语料 6 轮约需 2 小时 40 分以上）。
4. **判读这类负结果要注意区分两种可能**：一是模型容量不够，二是训练不充分。本题属于后者——8 层训练 loss 仍在大幅下降（153，尚未收敛），若延长到 20~30 轮，8 层很可能反超 4 层。
5. **后续建议**：若要真正验证规模效应，应固定 **token 预算**而非轮数，并同步加入 warmup 与学习率衰减；同时用多 seed 取平均，避免把 1%~3% 的噪声当成结论。
